# 用户笔记：把「划词 → 查词 → 听发音」真正用起来

适用版本：Easydict 2.23.0。记录日期：2026-10-29。

这份笔记面向想直接使用、部署给自己或朋友，以及继续改进这套功能的人。正文以本次真实排障为基础；未实际使用验证的内容会标成建议。

## 1. 安装前与安装

先装好官方 Easydict 2.23.0，并在 Terminal 中确认：

```bash
defaults read /Applications/Easydict.app/Contents/Info CFBundleShortVersionString
```

应显示 `2.23.0`。这个套件依赖内部方法，其他版本需要重新适配，不能只改版本号绕过检查。

解压套件后，在 Terminal 中输入 `cd `，把解压后的文件夹拖入 Terminal，再回车。随后执行：

```bash
python3 scripts/kit.py doctor
python3 scripts/kit.py install
```

如果系统提示缺少开发工具，运行 `xcode-select --install`，在系统窗口中完成 Command Line Tools 安装后重试。不需要完整 Xcode.app，也不需要 Python 第三方库。

安装过程先处理临时副本。编译或签名验证失败时，已安装的应用不会被替换。成功时会打印备份路径，建议把该路径保存到自己的使用笔记中。

## 2. 部署后最关键的一步：刷新授权

本次最大的经验是：**开关显示开启，不一定代表当前这份修改后的 app 已被授权。**

正确操作是：

1. 在 macOS 打开 **System Settings / 系统设置**。
2. 进入 **Privacy & Security / 隐私与安全 → Accessibility / 辅助功能**。这里不是左侧那个配置字体、缩放的通用「Accessibility」页面。
3. 在右侧应用列表中选中旧的 **Easydict**，点击减号，删除旧记录。
4. 如出现 Touch ID 或密码验证，由你本人完成。
5. 点击加号；在文件选择框按 `⌘⇧G`，输入 `/Applications/Easydict.app`，选择这份应用。
6. 开启它的开关。退出并重新启动 Easydict。

如果目录里还有 `Easydict.app.original_backup`，不要选它。备份与当前 app 可能名字相近、图标一样，但代码签名不同。

每次重新构建或签名后，都应重新完成实际划词验收；必要时重做以上步骤。安装器不代替用户授权，也不会要求额外的 Full Disk Access 来诊断这个问题。

## 3. 配置与日常使用

在 Easydict 设置中确认已开启自动划词、划词查询相关选项，并检查应用禁用列表没有屏蔽你正在阅读的软件。具体文字可能随界面语言而变化。

日常路径：

```text
拖选或双击英文词 → 小查词图标 → 悬停或点击 → 词典结果 → US/UK 扬声器
```

先用单词 `sixth` 验收。US/UK 按钮紧邻各自音标；顶部或结果底部的朗读按钮可能走默认 TTS，音色和词典按钮不一定相同。切换默认 TTS 不能代替测试 US/UK 按钮。

Google 等在线 TTS 依赖网络。只有自动朗读失败时，先检查对应服务；没有查词图标时，应先排查选词与权限，不要直接更换语音服务。

## 4. 一次完整验收

| 检查 | 怎么做 | 通过标准 |
| --- | --- | --- |
| 识别选词 | 在浏览器双击或拖选 `sixth` | 小图标出现 |
| 精确应用 | 在自己经常用的阅读/聊天应用再选一次 | 同样出现图标 |
| 打开结果 | 悬停或点击图标 | 查词结果对应选中的词 |
| US 发音 | 等上一段声音结束，点击 US 旁的扬声器 | 实际听到读音 |
| UK 发音 | 同样点击 UK 旁的扬声器 | 实际听到读音 |
| 重复点击 | 结束后再点一次 | 不会只有第一次有效 |
| 更换单词 | 换一个词，再打开结果与播放 | 新词正确，旧声音不会持续重叠 |

本次用户已确认查词按钮出现且 app 可用。日志证明播放器被调用，但给朋友部署时仍要请对方亲耳验收设备上的声音；日志不能替代耳机、扬声器和输出设备检查。

## 5. 遇到问题先看哪一层

| 现象 | 优先检查 |
| --- | --- |
| 完全没有小图标 | Easydict 是否运行、自动划词是否开启、当前 app 是否被禁用、Accessibility 是否对应新 app |
| 开关已开但日志报 `AXError.APIDisabled` | 删除旧行并重新添加当前 app；仅切换旧开关可能保留旧签名 |
| 图标出现但结果不对 | 实际选中的文本、是否连续触发了旧查询、词典服务结果 |
| 结果有音标但点了无声 | 是否装入了补丁、是否点击正确的 US/UK 按钮、对应音频请求及输出设备 |
| 顶部朗读正常、US/UK 无声 | 两条调用入口不同；不能用顶部朗读成功证明音标按钮正常 |
| 更新 app 后又失效 | 官方更新可能替换补丁；先核对版本，再适配，别直接向新版本重复注入 |

可运行 `python3 scripts/kit.py doctor` 做文件和签名检查。它明确只做静态检查，不会把「签名有效」写成「系统权限与发音全部正常」。更完整的排障步骤见 [SOP](SOP.zh-CN.md)。

## 6. 回退与迁移

需要回退时，先找到安装时打印的备份目录，然后：

```bash
python3 scripts/kit.py restore --backup "/你的备份目录/Easydict.app"
```

不要把备份目录放进 app 包内部。恢复后重做权限与选词验收。原有翻译偏好仍由 Easydict 管理，套件不复制或覆盖它们。

分享给别人时发送 GitHub 仓库链接或套件 ZIP。对方使用自己的官方安装包、设置和系统授权。不要发送自己的整个 Application Support 目录、TCC 数据库、API key 或完整日志。

## 7. 使用心得：本次可以直接分享的版本

> 这次我想解决的不是单独“让按钮有声音”，而是把“选词、出现入口、打开释义、听到发音”整条路径连起来。最初音标旁的按钮没有声音，原因是自定义补丁把第一次点击当成旧回调丢弃；修复后又遇到选词没反应，最终发现 macOS 还记着修改前那份 app 的授权。
>
> 最值得记住的一点是：不要只看设置开关，也不要只看编译成功。要在自己真实使用的软件里选一个词，打开结果，分别试听美音和英音。每次构建或更新之后，再走一遍这条路径，才能知道功能是否真的可用。

下面是建议养成的习惯，尚不代表经过长期学习效果评测：

- 阅读中先听一次，再自己复述；遇到 `six` / `sixth` 这样的词，把末尾音单独对比。
- 想比较英美发音时，固定使用对应的 US/UK 按钮，避免把不同 TTS 音色误认为口音差别。
- 记录问题时写明「哪个 app、哪个词、哪个按钮、是否出现小图标」，比一句“没有声音”更容易定位。
- 学习笔记可以记词义、音标、自己的发音难点与例句，使用心得不必混入所有实现细节。
